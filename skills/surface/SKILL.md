# surface — 세션에 묻힌 공유거리·질문을 끄집어내 초안으로

현재 대화 세션에서 **팀에 공유할 내용**과 **누군가에게 확인·질문해야 하는 모호한 지점**을 뽑아내, 대상별 전달 메시지 초안까지 만든다. 메신저 중립적이며(주 사용처는 Slack), **초안 출력이 끝이다 — 절대 직접 전송하지 않는다.**

## 언제 쓰나

작업을 어느 정도 하고 나서 "이 내용 팀에 공유해야 하는데", "이거 기획한테 물어봐야 하는데", "슬랙에 뭐라고 정리하지" 싶을 때. 사용자가 위 트리거 문구를 쓰거나 명시적으로 이 스킬을 부르면 실행한다.

## 절차

이 스킬은 **메인 컨텍스트에서 실행**되므로 지금까지의 세션 내용을 그대로 볼 수 있다. 세션을 새로 읽어올 필요 없이 아래 순서로 진행한다.

### 1) 세션 스캔 — 무엇을

지금까지의 대화에서 소통 가치가 있는 항목을 4종으로 뽑는다:

- **진행/완료**: 무엇을 했고 지금 어디까지 왔는가 (공유용)
- **결정사항**: 내려진 결정과 그 이유 (합의·기록용)
- **확인 필요 / 질문거리**: 내가 임의로 가정하고 넘어간 것, 스펙이 모호한 것, 판단이 갈리는 것 → **답을 받아야 진행이 확실해지는 것들**
- **블로커**: 남의 손이 필요해 막혀 있는 것

각 항목은 한 줄로 압축한다. 소통 가치가 없는 자잘한 것은 버린다. 뽑을 게 거의 없으면 그렇다고 솔직히 말하고 멈춘다.

### 2) 대상 분류 — 누구에게

각 항목에 대해 **답/조치를 할 수 있는 사람의 역할**을 붙인다: 기획/PM, 디자이너, 백엔드, 프론트, QA, 팀리드, 인프라, 우리 팀 전체 등. 세션에 실제 이름·핸들이 나왔으면 쓰고, 없으면 역할로 둔다(핸들은 초안에서 `[@…]`로 비워 사용자가 채우게 함).

같은 대상끼리 묶는다. 한 사람에게 갈 메시지 안에 질문 3개가 흩어지지 않게 한 덩어리로 정리한다.

### 3) 초안 작성 — 어떻게 (communicator 위임)

대상별로 **`communicator` 서브에이전트**(플러그인 등록 시 `softkit:communicator`)를 호출해 실제 메시지를 작성한다. 각 호출에 아래를 넘긴다:

- **intent**: 공유 / 질문 / 요청 등
- **audience**: 2)에서 정한 역할
- **facts**: 1)에서 뽑은 해당 대상용 항목들 (세션에서 확인한 사실만)
- **constraints**: 언어=한국어 존댓말(사용자가 달리 지정하면 그에 따름), 채널=Slack, 짧게

대상이 많지 않으면 한 번의 호출에서 여러 대상 메시지를 한꺼번에 요청해도 된다. communicator를 못 쓰는 환경이면 그 원칙(사실만·질문은 답하기 쉽게·핵심 먼저·짧게·존댓말)을 지켜 직접 작성한다.

### 4) 출력

- 먼저 **요약 체크리스트**를 보여준다: 뽑은 항목과 각 대상. 사용자가 대상/질문이 맞는지 눈으로 검증할 수 있게 한다.
- 그 아래 **대상별 메시지 초안**을 각각 코드블록으로 제시한다.
- `[@…]`, `[확인 필요: …]` 같이 사용자가 채워야 할 자리는 그대로 남긴다.
- 마지막에 한 줄: *"초안입니다. 대상과 내용을 확인하신 뒤 직접 보내주세요."* — 이 스킬은 전송하지 않음을 분명히 한다.

## 원칙

- **초안만.** 어떤 경우에도 Slack/메신저로 직접 보내거나 전송 도구를 호출하지 않는다.
- **사실만.** 세션에 없는 수치·날짜·담당자를 지어내지 않는다. 모르면 `[확인 필요]`로 남긴다.
- **질문은 답하기 쉽게.** 모호한 지점은 배경 한 줄 + 구체적 선택지 형태로 프레이밍한다.
- **적을수록 좋다.** 공유할 게 하나뿐이면 메시지도 하나만.
