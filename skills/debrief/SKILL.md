# debrief — 받은 말을 정리하고, 물어볼 것을 만든다

업무 중에 받은 말을 두고 세 가지를 정리한다.

1. **화자가 말하는 것** — 무엇을 주장하고 요청하는 것으로 보이는가
2. **불확실한 부분** — 이 글만으로는 알 수 없는 것이 무엇인가
3. **물어볼 것** — 그래서 누구에게 무엇을 물으면 되는가, 실제 질문 문장과 함께

## 판정하지 않는다

이 스킬은 결론을 내리지 않는다. 화자의 말이 옳은지, 어느 해석이 맞는지, 사용자가 무엇을 해야 하는지는 정하지 않는다.

이유는 이렇다. 받은 말이 어려운 것은 대개 글에 정보가 빠져 있기 때문이고, 빠진 정보는 읽는 쪽이 아무리 궁리해도 채워지지 않는다. 그런데 AI가 그럴듯한 해석을 내놓으면 사용자는 그것을 사실처럼 받아들여 움직이게 된다. 해석이 틀렸을 때 비용은 사용자와 동료가 치른다. 반면 화자에게 한 번 묻는 것은 싸고 확실하다. 그래서 이 스킬의 산출물은 "답"이 아니라 **좋은 질문**이다.

구체적으로는 이렇게 쓴다.

- "~라는 뜻입니다" 대신 "~라고 말하는 것으로 보입니다", 그리고 그렇게 본 원문 대목.
- "이 지적은 맞습니다/과합니다" 대신 확인한 사실만. 사실과 주장이 어긋나 보이면 그것을 불확실한 부분으로 올린다.
- "~하시면 됩니다" 대신 물어볼 것. 다음 행동은 답을 받은 사용자가 정한다.
- 화자의 감정이나 속마음은 다루지 않는다. 사용자가 "화난 건가"처럼 물어도 글만으로는 알 수 없다고 한 줄로 답하고 넘어간다.

## 절차

이 스킬은 **메인 컨텍스트에서 실행**되므로 지금까지의 세션과 저장소를 그대로 볼 수 있다.

### 1) 원문 확보

- 사용자가 붙여넣은 글이 있으면 그것이 원문이다.
- PR·이슈 번호나 URL만 주었으면 `gh`로 본문과 코멘트를 읽어 온다. 조회만 하고 GitHub에 아무것도 쓰지 않는다.
- 슬랙·메일처럼 직접 읽을 도구가 없는 곳의 글은 붙여넣어 달라고 요청한다.

### 2) 화자가 말하는 것 정리

원문을 주장과 요청 단위로 나누고, 원문에 그대로 쓰인 것과 미루어 본 것을 구분한다. 미루어 본 항목에는 그렇게 본 근거가 된 원문 구절을 짧게 붙인다.

- **명시** — 문장에 그대로 쓰여 있다.
- **추정** — 쓰여 있지는 않지만 문맥상 그렇게 보인다. 질문 형태로 쓰인 변경 요청("이렇게 하신 이유가 있을까요?")이 대표적이다.

두 가지 이상으로 읽히면 하나를 고르지 않는다. 어느 쪽인지가 곧 불확실한 부분이 되고, 질문의 선택지가 된다.

### 3) 찾아볼 수 있는 것은 찾아본다

질문을 만들기 전에, 묻지 않고도 풀리는 것을 먼저 푼다. 찾아보면 나오는 것을 화자에게 묻게 만들면 사용자가 곤란해진다.

| 걸리는 것 | 찾는 곳 |
|---|---|
| 파일명·함수명·브랜치명·에러 메시지 | 저장소 검색과 파일 읽기, `git log`, `git status` |
| "아까 그 건", "지난번 그 방식" 같은 지시어 | 현재 세션의 앞선 대화, 관련 PR·커밋 |
| 일반 기술 용어·약어 | 아는 범위에서 한 줄로 |
| 사내 용어·서비스명·팀 고유 약어 | 저장소 문서와 코드. 없으면 불확실한 부분으로 |

확인한 것은 출처(파일 경로와 줄, 커밋, 세션의 어느 대목)와 함께 적는다. 찾지 못한 것을 그럴듯하게 채우지 않는다. 일반 지식으로 푼 약어는 팀에서 다른 뜻으로 쓸 수 있으므로 추정으로 표시한다.

찾아봤지만 나오지 않은 것은 출력에 적지 않는다. 원문이 지금 저장소와 무관한 이야기라면(다른 저장소의 코드, 저장소 밖의 업무) 검색은 한 번으로 끝내고 넘어간다. "검색했으나 없음"은 사용자에게 정보가 아니다.

### 4) 불확실한 부분 가려내기

3)을 거치고도 남은 것이 불확실한 부분이다. 흔한 유형은 다음과 같다.

- **가리키는 대상** — "이 부분", "그 케이스", "지난번 방식"이 무엇인지
- **요청의 강도** — 꼭 해야 하는 것인지 의견인지, 이번에 할 것인지 나중인지
- **기한과 범위** — 언제까지, 어디까지
- **빠진 전제** — 대화에 없는 사람의 결정, 선행 작업, 화자가 본 화면이나 값
- **사실과의 어긋남** — 화자의 말과 저장소에서 확인한 사실이 다를 때. 누가 틀렸는지 정하지 말고, 화자가 무엇을 보고 말했는지를 물을 거리로 삼는다

**답에 따라 사용자의 행동이 달라지는 것만** 남긴다. 알아도 할 일이 바뀌지 않는 것까지 늘어놓으면 정작 물어야 할 것이 묻힌다. 대부분 1~3개면 충분하다.

### 5) 질문 만들기 — communicator 위임

불확실한 부분마다 누구에게 무엇을 물을지 정한 뒤, 실제 질문 문장은 **`communicator` 서브에이전트**(플러그인 등록 시 `softkit:communicator`)에 맡긴다. communicator는 세션을 볼 수 없으므로 아래를 프롬프트에 그대로 담아 넘긴다.

- **intent**: 질문
- **audience**: 화자의 역할(리뷰어, 기획자 등). 이름이 원문에 있으면 함께
- **facts**: 받은 원문, 묻고 싶은 불확실한 부분, 3)에서 확인한 사실 중 질문에 꼭 필요한 것
- **constraints**: 아래를 그대로 넘긴다
  - 채널: 원문이 온 곳(슬랙, PR 코멘트 등). 모르면 슬랙으로 둔다
  - 같은 사람에게 가는 질문은 한 메시지로 묶고, 메시지 전체는 8줄 이내
  - 질문만 한다. "반영하겠습니다", "바로 진행하겠습니다"처럼 행동을 약속하는 문장을 넣지 않는다. 무엇을 할지는 답을 받은 뒤 사용자가 정한다
  - 갈리는 해석 중 하나를 골라 "~로 이해했습니다"라고 쓰지 않는다. 선택지로 나란히 제시한다
  - 원문에 없는 후보(화자가 말하지 않은 대안 등)를 선택지에 넣지 않는다
  - 확인한 사실을 길게 나열하지 않는다. 질문을 이해하는 데 필요한 한 줄만
  - 한국어 합니다체

`draft`는 넘기지 않는다.

돌아온 메시지는 그대로 싣지 말고 위 제약을 지켰는지 확인한다. 어긴 곳이 있으면 직접 고친다. 질문 예시는 사용자 이름으로 나갈 문장이므로, 사용자가 하지 않은 약속이나 고르지 않은 해석이 들어가 있으면 안 된다. communicator가 덧붙인 "바뀐 부분"이나 "메모"는 출력에 옮기지 않는다.

communicator를 쓸 수 없는 환경이면 위 제약을 지켜 직접 쓴다.

## 출력

이 스킬의 결과는 대부분 터미널에서 텍스트로 읽힌다. 화면을 넘기는 순간 읽히지 않으므로, 아래 형식을 **그대로** 쓰고 여기에 없는 절이나 문단을 더하지 않는다.

````markdown
**요약** [화자가 바라는 것으로 보이는 바를 한 문장으로]

**화자가 말하는 것**
1. [주장 또는 요청] (명시)
2. [주장 또는 요청] (추정: "근거가 된 원문 구절")

**확인한 것**
- [사실] — [출처]

**불확실 → 물어볼 것**
1. [무엇을 알 수 없는지] → [누구]에게
2. ...

**질문 예시** ([누구], [채널])
```
[메시지]
```
초안입니다. `[ ]` 자리를 채우고 내용을 확인하신 뒤 직접 보내주세요.
````

절마다 지키는 것:

| 절 | 분량 | 규칙 |
|---|---|---|
| 요약 | 1문장 | 결론이 아니라 화자의 말을 줄인 것 |
| 화자가 말하는 것 | 최대 4항목, 항목당 1줄 | 원문 인용은 추정 항목에만, 핵심 구절만 짧게 |
| 확인한 것 | 최대 3줄 | 찾아서 확인한 사실은 출처와 함께, 일반 지식으로 푼 용어는 `(일반 지식)`으로 표시. 용어 풀이는 여기에만 두고 다른 절에 섞지 않는다. 없으면 절을 통째로 생략 |
| 불확실 → 물어볼 것 | 최대 3항목, 항목당 1줄 | 이유 설명을 붙이지 않는다 |
| 질문 예시 | 8줄 이내 | 받는 사람이 여럿이면 사람마다 하나씩 |

형식 밖의 말이 꼭 필요하면 맨 끝에 `참고:`로 시작하는 줄을 최대 두 줄 둔다. 쓰는 경우는 두 가지다. 사용자가 화자의 감정을 물었을 때("참고: 화가 났는지는 글만으로는 알 수 없습니다"), 그리고 임의로 둔 가정을 밝힐 때("참고: 채널은 슬랙으로 가정했습니다").

쓰지 않는 것: 표, 헤더(`#`), 해석 후보를 나열한 코드블록, 다음 행동 제안, 마무리 인사.

불확실한 부분이 없으면 **요약**과 **화자가 말하는 것**만 쓰고 마지막 줄에 "물어볼 것은 없습니다."라고 적는다.

**예시**

원문: "배포 전에 그 설정 확인 부탁드립니다. 지난번처럼 되면 안 될 것 같아서요."

````markdown
**요약** 배포 전에 어떤 설정을 확인해 달라는 요청으로 보입니다.

**화자가 말하는 것**
1. 배포 전에 설정을 확인해 달라 (명시)
2. 이전 배포에서 이 설정 때문에 문제가 있었다 (추정: "지난번처럼 되면")

**불확실 → 물어볼 것**
1. "그 설정"이 어느 설정인지 → 작성자에게
2. "지난번"에 무슨 일이 있었는지 → 작성자에게

**질문 예시** (작성자, 슬랙)
```
[@작성자] 배포 전 확인 건으로 두 가지 여쭙니다.
1. 말씀하신 설정이 어느 설정인지 알려주시기 바랍니다.
2. 지난번에 어떤 문제가 있었는지도 알려주시기 바랍니다.
```
초안입니다. `[ ]` 자리를 채우고 내용을 확인하신 뒤 직접 보내주세요.
````

## 경계

- **전송하지 않는다.** 질문 예시는 초안이다. 슬랙·GitHub 등에 직접 보내거나 쓰지 않는다.
- **사람을 평가하지 않는다.** 문장에 대해서만 말한다.
- **사용자가 판정을 직접 요구해도** ("그래서 이 말이 맞아?") 형식은 바꾸지 않는다. 확인된 사실은 **확인한 것**에, 사실로 가려지지 않는 부분은 **불확실 → 물어볼 것**에 넣는다. 옳고 그름은 사용자가 그 둘을 보고 정한다.
